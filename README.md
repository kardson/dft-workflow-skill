# DFT Workflow Toolkit

**使用 AI agent 开展 VASP DFT 模拟计算的工作流。**

科研人员提出研究问题、提供材料并确认方案，agent 协助核对环境、规划计算、准备输入、检查设置、在批准范围内执行与取证，再分析和解释结果。本仓库提供支撑这些步骤的通用工具、协作说明和记录模板。

**基本顺序：环境就绪 → 明确研究问题 → 确认计算方案 → 准备与检查 → 执行与取证 → 分析与科学判断。**

你可以用自然语言与 agent 协作。工具调用、文件格式和过程记录由 agent 处理；你主要关注为什么要算、方案是否合理、预计代价和结果能说明什么。

## 先让 agent 核对使用环境

第一次使用前，先准备好自己的计算环境和私有研究工作区，再请 agent 核对这套工作流是否能在其中使用。已有可用环境应优先复用。

| 环境部分 | Agent 需要核对什么 |
|---|---|
| Agent 的文件与工具权限 | 能否在指定范围内读取材料、调用本地工具；是否已读本仓库 [AGENTS.md](AGENTS.md) 和私有项目规则 |
| 工作流工具环境 | 仓库位置、实际 Python 路径与版本、当前任务所需依赖及可用工具 |
| VASP 计算环境 | 合法软件与赝势、软件版本、赝势来源、计算资源、运行目录和启动方式 |
| 私有研究工作区 | 模型、文献、输入输出、分析及连接配置的位置，允许读写和执行的范围 |

如果还缺少配置，可以请 agent 说明缺项、协助完成允许范围内的配置和检查，并留下环境记录。需要软件许可或服务器管理权限的部分，由具备相应权限的人完成。仅分析已有结果时，可先核对分析所需环境。

可以这样向 agent 提出请求：

> 请核对我提供的工具库、私有研究目录和 VASP 环境，说明哪些功能已可用、还缺什么，以及必要的配置步骤。复用可用环境，保留现有数据，按我允许的范围完成配置与检查，交付环境记录。

环境记录应明确实际版本、路径、可用功能和证据。工具能正常运行与计算环境适合本研究，需要分别确认。

## 向 agent 提供研究目标

环境就绪后，用自然语言说明以下内容。不了解参数时，先请 agent 解释方案与依据，再结合负责该研究的人员作选择。

- **想知道什么：** 一个具体材料或物理问题，以及预期得到的性质或比较。
- **已有材料：** 结构、文献、已有方案、实际输入输出及它们的位置。
- **已确定与未确定的选择：** 模型、方法、参数、参照和收敛要求；未知项也如实说明。
- **资源与预期：** 可用计算资源、时间、预算和本次希望得到的交付。
- **允许范围：** 本次允许规划、准备、分析、查询还是运行，以及停止条件。

例如：

> 我想比较两种候选结构的稳定性，结构和已有结果在指定的私有目录中。请先检查已有证据是否可比，说明还缺什么，再提出计算方案、预计成本和接受条件。方案确认后，按批准范围完成计算和分析，并解释结果支持什么判断。

Agent 应先检查已有结果是否足够，说明新增计算将补哪条证据，避免重复计算。公开工具不提供一套适用于所有材料的默认研究参数。

## Agent 怎样推进计算

| 阶段 | Agent 的工作 | 科研人员需要判断什么 |
|---|---|---|
| **明确问题** | 读取指定材料，核对已有证据，列出缺口 | 研究问题是否明确，是否确实需要新计算 |
| **提出方案** | 说明模型、方法、参照、精度、成本和停止条件 | 方案依据与代价是否合理，哪些科学选择仍需讨论 |
| **准备与检查** | 在支持范围内准备候选输入，核对实际结构、参数、约束、赝势环境和重启来源 | 是否按已确定的方案准备，执行范围是否清楚 |
| **执行与取证** | 在已适配的部署和授权范围内处理运行、状态查询与证据回收 | 是否有真实启动证据，异常和缺失是否被记录 |
| **分析与解释** | 核对输出、收敛与可比条件，整理数据，解释结果及限制 | 结果能否回答研究问题，是否适合支持本次结论 |
| **决定下一步** | 更新任务卡与证据链接，提出必要的后续动作 | 接受结果、补证、修改方案，还是暂不新增计算 |

明确计算获准后，agent 应完成允许范围内的准备、检查和必要机械修正，减少同一范围的反复确认。改变方法、结构来源、重启策略或扩展计算范围时，需要作新的决定。

实际执行需要自己的 VASP 部署与启动适配。各工具有明确支持范围，公开仓库不附工作站专用配置；agent 应根据实际环境说明能完成哪些步骤。通用检查入口本身不负责提交计算。

## 用任务卡掌握进展

由 agent 在私有工作区维护一张简明当前任务卡。你可以先读卡片，需要细节时再查看原始证据和技术记录。

| 项目 | 卡片应回答的问题 |
|---|---|
| 研究问题 | 本次要回答什么？ |
| 当前阶段 | 已准备、已启动、结果已返回，还是已完成科学审阅？ |
| 证据与时间 | 实际输入或主输出在哪里，最后核实是什么时候？ |
| 下一步与负责人 | 接下来做什么，由谁处理，允许范围是什么？ |
| 结论与限制 | 目前知道什么，还有哪些不确定性？ |

任务卡在同一位置更新，历史记录保留，避免多份“当前状态”互相矛盾。结构、文献、计算输入输出、连接配置和分析结果都放在独立私有工作区，agent 显式绑定对应路径。

参考：[私有工作区说明](docs/private_workspace.md)、[协作流程](docs/workflow.md)、[任务记录模板](templates/task_record.template.json)、[交接模板](templates/handoff.template.md)。

## 让 agent 把结果解释清楚

结果报告应先用日常语言说明：**原本想知道什么、实际观察到什么、依据在哪里、结论可信到什么程度、下一步由谁决定。** 再附主输出、参数与检查依据。

| 看到的状态 | 应怎样理解 |
|---|---|
| 输入已准备 | 候选文件到位，还不能说明计算已运行 |
| 已启动 / `RUNNING` | 在记录的观察时间有启动或运行证据，历史快照不保证现在仍在运行 |
| 正常退出 / 退出码 0 | 对应程序或检查完成，仍需核对输出、收敛条件和警告 |
| `BLOCKED` | 当前前提不足，应由 agent 说明具体缺口和解决所需的决定或材料 |
| `UNKNOWN` / `PARTIAL` | 证据缺失或不完整，暂时无法作完整判断 |
| 结果已接受 | 应有科学审阅的依据、限定用途和仍然存在的限制 |

比较能量、结构或电子性质时，要核对方法、赝势、数值设置、参照及相关收敛条件。Agent 可以协助核查和解释，科学结论仍须有实际证据支持。文件齐全或程序检查通过，不能单独证明科学结论成立。

## 支持范围与环境参考

当前主要支持 VASP 工作流。Python 源码语法要求为 **3.10+**；已记录的科学安装组合主要为 **Windows AMD64 / Python 3.12.14**。VASP 配置参照版本为 **6.5.1**，VASPKIT 集成记录参照版本为 **1.5.1**，其他版本不能视为已验证。

科学几何与解析功能按需使用 `requirements-science.txt`，附加分析按需使用 `requirements-analysis.txt`；基础规划、契约检查和证据工具只依赖 Python 标准库。具体依赖、复现方法与限制供 agent 或配置人员查阅：

- [兼容记录](docs/compatibility-clean-science.json)
- [环境复现说明](docs/reproduce-clean-science.md)
- [依赖与第三方说明](THIRD_PARTY.md)

## 验证、贡献与许可

已有安装和合成验证提供有限的工具证据；真实诊断覆盖、真实科研效率收益和外部首次使用者体验仍有未验证部分。目前不能据此承诺科研节时或诊断准确率。

验证范围与补充证据见[诊断范围](docs/diagnostic-validation-scope.json)、[诊断补充](docs/diagnostic-validation-supplement.json)、[字段核验说明](docs/evidence-verifier.md)、[工作流观察合同](docs/workflow-observation-contract.json)和[合成试用证据](docs/workflow-evidence-supplement.json)。

可以通过 issue 或 PR 提交通用改进。维护者在维护源中合入，再按公开清单生成发布；`release_manifest.json` 记录公开文件和完整性摘要。贡献中使用合成数据，真实研究内容和配置保留在私有工作区。开发与验证要求见 [AGENTS.md](AGENTS.md) 和[公开内容与贡献要求](docs/publication_policy.md)。

**本工具库尚未指定许可证。** 使用与再分发前请向维护者确认授权；第三方软件遵守各自许可。
