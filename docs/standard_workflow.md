# Agent 六步标准流程

研究者提出问题、提供材料并确认方案；下列工具、格式和引用由 agent 处理。实际数据与配置保留在独立私有工作区，显式设置 `DFT_WORKSPACE_ROOT`。工具根为本仓库 `tools`；科学与扩展分析可以使用不同的现有 Python 环境。

| 步骤 | 入口与记录 | 交付及边界 |
|---|---|---|
| 1. 环境就绪 | `environment_check.py` 的 tools、workstation、review、combine；环境检查模板 | 固定完整清单，核对工具依赖、执行软件、编译功能、赝势、资源和运行目录。工具侧通过不能代替工作站核实；未证实项保留未知，不启动计算来冒充检查。 |
| 2. 明确问题与材料 | `intake.py`；research_intake 模板 | 提问并引用实际答复，列已有、找到、取得及缺失材料。检索命中不等于取得；受限材料说明检索、限制及用户补充要求。 |
| 3. 确认方案 | `planning.py`、`plan_templates.json`；calculation_plan 和 calculation_proposal 模板 | 目标、模型方法、依赖顺序、精度比较、资源成本、交付停止六项内容。未知成本说明原因。检查通过仅表示可审阅；用户确认后才能作为准备依据。 |
| 4. 准备与检查 | 既有输入生成器及静态/固定胞包构建器；`preparation.py`；plan_approval 模板 | 生成完整包，检查实际文件与批准规格、赝势身份及重启契约。绑定批准来源、数值规格和运行约定；机械修正本步完成，科学改变回到方案讨论。 |
| 5. 执行与取证 | 既有部署适配、`job_watch.py`、`execution.py`、`recovery.py`；execution_authority 模板 | 既有授权内启动，核实真实推进后交付并结束；普通程序记录状态。一次性查询，终态才回收。回收固定清单、预算、身份与完整性均核实，缺项保留部分结果。 |
| 6. 分析与科学判断 | `analysis.py` analyze/render、`analysis_templates.json`；result_review 模板 | 复用 pymatgen/ASE 与执行后检查，核对完整性、实际设置和收敛。区分事实、解释、限制与科学接受，附数据/图表/方法来源，更新当前任务卡。 |

当前类型目录包括 static、atomref、relax_fresh、relax_warm，采用固定胞、无外场、无 SOC 的已支持范围。目录不指定通用数值参数；其他科学方法须另行建立有依据的方案和验证。参考既有工具的帮助与合成测试完成具体调用，不将测试数值用于研究。

固定胞包构建器需要明确的工作站环境描述，不读取随库提供的默认工作站配置。运行前按本地规则完成部署适配、实际环境和批准范围核验。记录中的许可或授权引用必须来自真实用户答复。

静态和原子参照包在准备检查通过后，使用 `static_status_binding.py` 生成独立监督附件。它保留原包，检查来源与实际文件，产生本次执行身份、watch 配置及上传清单。附件按原部署授权放入同一 batch，保留原批准门与运行脚本，由监督入口启动；后续查询、授权记录和回收绑定附件中的 `status_manifest.json`。仅准备附件不授予部署或执行权限。已有计时或身份冲突时拒绝复用，不自动重试。

标准分析提供第 4 步的准备检查记录，绑定方案与候选数值规格。对来源变化、部分解析和未收敛保持明确结论。额外分析仅使用批准范围中的实际数据，并记录来源、方法和比较条件；文件存在或程序退出成功均不构成科学接受。

准备交接也绑定输出要求，分析不能替换为较弱要求；旧交接缺少绑定时重新检查。实际分析器完成但输出不完整才记为 PARTIAL。分析程序启动失败、超时或异常退出记为后端 FAILED、解析 UNAVAILABLE，不能交付为结果。最终交付前重新核对回收记录指向的实际输出及后端记录，变化时停止交付并重新取证分析。

固定胞 fresh/warm 准备审计先从批准合同重建规范输出要求，逐项核对实际文件，包含字段、列表、嵌套值及类型；仅重算包内校验信息不能证明批准一致性。检查有阻塞时，不生成供分析使用的输出要求摘要。

任务卡由指定写入者在同一位置维护。结果交付只更新 `AGENT_TASK_CARD_BEGIN:<task_id>` 与对应 END 标记之间的本任务区域，保留其余历史。已有卡片无匹配标记时先由负责写入者接入；不得直接覆盖。

所有步骤的通过状态都不能代替科学判断。结果由负责研究的人审阅；补算、重启、方法或范围变化遵循原有决策与授权边界。
