# 继续当前任务

用户说“继续上次任务”时，先从指定工作区和任务卡定位实际任务；有多个候选就确认任务身份，不全盘扫描或猜最新目录。读取原始批准、实际执行身份及当前写入者。

Agent 在任务阶段交付时，可维护私有 dft-continuation/v1 JSON：task_id、stage、writer、approval_scope、evidence。stage 为 DRAFT/PLANNED/PREPARED/SUBMITTED/RUNNING/TERMINAL/RECOVERED/ANALYZED/ACCEPTED；必须依据真实记录，科学接受不能由 agent 自行标记。evidence 是非空列表，每项 path（工作区内实际引用）及 sha256（记录时实际文件身份）。身份摘要仅用于检测恢复时证据变化。先保存所有相关实际回执，再生成继续记录；不以继续记录代替批准或原始输出。

调用 tools/task_resume.py --help 获取入口，传 --record、--workspace 和工作区内新的 --output。工具验证记录引用和变化，不调用远端、不写任务卡、不执行建议。历史 RUNNING 只建议按当前请求一次查询，不证明还在运行；PREPARED 不建议重复生成或自动提交。缺失或变化先核对来源，禁止以重算摘要掩盖变化。

没有继续记录的旧任务先读任务卡、原始批准和对应回执，由负责写入者整理并核对身份，再建立记录。未能确认的状态报告 UNKNOWN，不伪造过去完成步骤。恢复后依然核对本次授权和唯一写入者；原有在途任务不因换会话重复启动。

## 阶段交付时生成记录

已具备准备、启动、回收或分析回执时，优先调用 tools/task_checkpoint.py（先读 --help），传入实际 --receipt、--workspace、--task-id、--writer 和新 --output。工具从支持的成功回执推导阶段，不接受任意 stage 参数，不覆盖历史记录，也不记录科学接受。主控先核实回执真实性；工具并不重新执行回执指向的科学检查。

每次保留独立继续记录，在当前任务卡链接最新记录。启动回执只证明当时已启动；缺乏启动证据的失败回执不得生成 RUNNING。解析后端失败不得生成 ANALYZED。恢复时先核对记录，再按原步骤重验实际输入、原始输出与批准绑定；仅回执文件未变不证明其全部传递来源未变。

继续记录还会核对回执中的带摘要来源引用，以及回收记录中的原始输出文件。恢复时会直接检查这些文件，不能仅凭回执自身未变就认为分析证据未变。启动记录依然只代表历史观察，不构成新的运行确认。

阶段交付时传 --task-card 可更新已有任务标记内的继续记录子区块，保留本任务研究说明及其他任务。只有负责写入者可维护；已有卡片缺少匹配标记时先接入，不能覆盖。重复接入只更新同一子区块。
