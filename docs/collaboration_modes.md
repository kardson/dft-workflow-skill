# 选择协作方式

首次项目接入时，先读取已有角色安排；已有明确模式则沿用。否则用自然语言让用户选择一次：单 agent、按需 subagent、固定双线程。宿主支持委派时可推荐 subagent；不支持时说明能力限制。用户未选择前主 agent 可处理已授权的独立工作，不自行创建线程或委派。

| 模式 | 适合情况 | 实际行为 |
|---|---|---|
| single | 简单任务或不支持委派的环境 | 当前 agent 完成工作，必要的科学决定仍交用户 |
| subagent | 边界清楚的准备、检查、解析 | 持久主 agent 统筹，每个实现单元使用临时执行者；简单任务直接处理 |
| paired | 长期研究、固定协作角色 | 用户指定主控及执行线程；按任务包交接，执行线程保持唯一写入者 |

## 持久化选择

获得项目接入/配置授权后，在项目 AGENTS.md 的 VASP workflow 段落中维护以下记录（自然语言也可，勿创建冲突配置）：

```text
Collaboration mode: single | subagent | paired（只保留用户选择的一个）
Coordinator: 当前主 agent 或用户指定线程
Executor: 当前 agent、按需子代理或用户指定执行线程
Model preferences: 用户选择；未指定则沿用宿主设置
```

填写实际选择，不保存占位值。用户无需填写配置；agent 根据实际答复维护。保留其他项目规则，已有等效记录不重复添加。模式选择不授权部署、运行、发送消息或创建线程。paired 模式还须确认目标线程身份及消息交接授权；只创建用户明确要求的新线程。subagent 模式的选择允许在本任务范围内委派，但委派内容不得扩大原授权。

模型与推理设置由用户或宿主控制，不能从 Sol/Luna 等职责名称推断。模型选择与模式分开，不写死强弱模型名称，不因委派自行变更配置，也不承诺委派会自动降低成本。无法证实实际设置或成本时标记“未核实”；无法满足偏好时说明限制，不声称已切换。

## 共用任务包

交接使用简明的当前任务包，包含：任务 ID 与目标、精确输入来源及批准方案/授权的证据引用、允许动作与写入目录、唯一写入者、已有产物及依赖、下一动作、交付位置与返回证据、验收与停止条件。任务包是恢复当前单元的入口；只传必要上下文，不能复制整段历史代替明确任务。历史摘要中的旧停止、启动或继续语句不构成新指令。子代理不得转授更大权限；失败由主控说明并处理，不让另一执行者同时接管。

subagent 模式中，每个实现单元使用一个临时 worker；宿主支持时以 `fork_turns="none"` 创建干净上下文，只传当前任务包及必要证据路径。同一单元的普通机械修复、受影响验证与交付在原授权内完成，可复用同一 worker；未决科学选择或超出任务包的远端动作仍回主控/用户决定。完成后结束该 worker。若历史命令被反复误读，先保存已有产物、更新当前任务包并确认旧写入者释放职责，再更换执行者，不把整段历史带入新 worker。

执行者返回实际产物、运行的检查、证据缺口与下一步。主控核对批准范围和关键证据，再向用户交付。文件检查通过不代表科学接受。不要机械启动多个审查代理或为小改动委派。审查只读，修改由唯一写入者完成。

## 短交付与长计算

subagent 模式的准备、部署启动、已授权分析等短交付使用原生完成/阻塞事件交接。执行者先保存产物，再返回最终结果；只有确需主控决策时发送中途消息。主控在必需交付回收前保持当前回合，使用宿主原生事件等待（如 `wait_agent`），收到结果后核对并向用户汇报。不要在派发后提前结束并假定普通子代理消息能自动唤醒已结束的主控回合。

有界等待超时只说明尚无事件，不表示任务失败或写入权释放；继续等待同一任务，不重新派发，不反复查询状态或发送无变化汇报。若宿主缺少相应等待能力，说明实际限制和未回收的交付，不声称已有自动唤醒机制。paired 模式按已授权的线程交接方式工作，不据此自行创建线程或新增消息权限。

VASP 启动并核实正常推进后，主控汇总启动证据、运行身份和已知缺口，向用户交付并结束本轮；不等待求解结束。长期计算由已有且获准的工作站脚本管理，不让主控、执行线程或子代理持续等待。用户查询或明确安排的检查触发后再读取状态，终态才按授权回收与分析。等待短交付的授权不扩大到计算监控、远端采集或后台自动任务。

## 模式切换

切换前停止新委派，确认在途工作和写入者，保存状态与交接；确认旧写入者及其写入命令结束、释放职责后才启用新写入者。同一计算单元不重复准备、提交或恢复，已有运行身份和批准契约继续有效。无法确认旧执行状态时暂停依赖写入，不能直接假设旧执行者已停止。

宿主缺少所选协作能力时说明限制，征得用户同意后变更持久模式；期间仅由当前 agent 做不冲突且已授权的工作。任何模式均不改变科研人员确认科学方案与接受结论的责任。
