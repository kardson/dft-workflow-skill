# 选择协作方式

首次项目接入时，先读取已有角色安排；已有明确模式则沿用。否则用自然语言让用户选择一次：单 agent、按需 subagent、固定双线程。宿主支持委派时可推荐 subagent；不支持时说明能力限制。用户未选择前主 agent 可处理已授权的独立工作，不自行创建线程或委派。

| 模式 | 适合情况 | 实际行为 |
|---|---|---|
| single | 简单任务或不支持委派的环境 | 当前 agent 完成工作，必要的科学决定仍交用户 |
| subagent | 边界清楚的准备、检查、解析 | 主 agent 统筹，按功能批次委派；简单任务直接处理 |
| paired | 长期研究、固定角色和模型 | 用户指定主控及执行线程；按任务包交接，执行线程保持唯一写入者 |

## 持久化选择

获得项目接入/配置授权后，在项目 AGENTS.md 的 VASP workflow 段落中维护以下记录（自然语言也可，勿创建冲突配置）：

```text
Collaboration mode: single | subagent | paired（只保留用户选择的一个）
Coordinator: 当前主 agent 或用户指定线程
Executor: 当前 agent、按需子代理或用户指定执行线程
Model preferences: 用户选择；未指定则沿用宿主设置
```

填写实际选择，不保存占位值。用户无需填写配置；agent 根据实际答复维护。保留其他项目规则，已有等效记录不重复添加。模式选择不授权部署、运行、发送消息或创建线程。paired 模式还须确认目标线程身份及消息交接授权；只创建用户明确要求的新线程。subagent 模式的选择允许在本任务范围内委派，但委派内容不得扩大原授权。模型选择与模式分开，不写死强弱模型名称；无法满足偏好时说明限制，不声称已切换。

## 共用任务包

交接包含：任务 ID、研究目标、批准方案及引用、输入来源、允许动作与目录、唯一写入者、输出位置、验收与停止条件、依赖、返回证据。只传必要上下文，不能复制整段历史代替明确任务。子代理不得转授更大权限；失败由主控说明并处理，不让另一执行者同时接管。

执行者返回实际产物、运行的检查、证据缺口与下一步。主控核对批准范围和关键证据，再向用户交付。文件检查通过不代表科学接受。不要机械启动多个审查代理或为小改动委派。审查只读，修改由唯一写入者完成。

## 模式切换与长计算

切换前停止新委派，确认在途工作和写入者，保存状态与交接；旧写入者释放职责后才启用新写入者。同一计算单元不重复准备、提交或恢复，已有运行身份和批准契约继续有效。无法确认旧执行状态时暂停依赖写入，不能直接假设旧执行者已停止。

启动并核实正常推进后交付、结束本轮。工作站普通程序记录状态，不让主线程、执行线程或子代理持续等待。用户查询或明确安排的检查触发后再读取状态，终态才按授权回收与分析。

宿主缺少所选协作能力时说明限制，征得用户同意后变更持久模式；期间仅由当前 agent 做不冲突且已授权的工作。任何模式均不改变科研人员确认科学方案与接受结论的责任。
