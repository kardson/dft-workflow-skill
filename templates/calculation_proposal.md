# 计算提案

给研究者的正文尽量用日常语言填写。软件参数和运行身份放在“技术附录”，不让用户靠猜测选择科学方法。

## 给研究者看的提案

- **研究问题：** 这项计算想回答什么？
- **为什么现在要做：** 已有结果是什么？还缺哪一条证据？
- **本次方案：** 模型、计算方法和比较对象是什么？这些选择由谁裁决？
- **预期成本：** 大约需要多久、多少计算资源或人工操作？无法估计时写“尚未估计”。
- **结果如何判断：** 哪些可观察结果会支持、反对或无法区分预期解释？
- **停止条件：** 出现什么情况时停止并交回判断，不继续自动扩展计算？
- **本次批准范围：** 仅准备，还是包括运行、结果回收或分析？批准后会在哪个节点交回？
- **本次不会回答：** 列明仍未解决的科学问题和本结果的适用边界。

- **路线 / 稳定任务编号：**
- **模型和结构来源：**
- **软件与方法：**
- **关键设置及理由：**
- **边界条件、原子约束、外场定义：**（不适用时写“不适用”）
- **收敛或对照要求：**（例如基组、网格、厚度、构型或零场对照，按本问题填写）
- **初始结构与重启来源：**（明确写新计算或经过核验的重启）
- **预期交付文件和证据：**
- **准确授权范围、执行人和停止点：**
- **拟用结果及接受条件：**
- **依赖及出处：** 链接到已有批准规格、文献或原始证据；不要复制另一份参数台账。

## 审批记录

- **科学方案裁决：** 待定 / 已裁决；裁决人、日期和记录链接：
- **用户执行授权：** 待批准 / 已批准 / 仅限本地准备；具体授权内容、日期和记录链接：
- **执行状态：** 尚未准备 / 已准备 / 已启动 / 已返回 / 待科学审阅 / 已审阅

科学方案裁决和用户对具体执行动作的授权是两件不同的事。未裁决的科学选择不能留给执行者或用户在批准框里猜；未明确授权的运行、续算、参数扫描或其他动作不能从相近任务推定。
